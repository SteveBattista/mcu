# GitHub Issues Cheat Sheet

## Open a New Issue (Web UI)

1. Go to the repository on GitHub.
2. Click the **Issues** tab.
3. Click **New issue**.
4. If templates are shown, pick the right one or click **Open a blank issue**.
5. Fill in:
   - **Title** — short, descriptive summary
   - **Description** — what is wrong / what is needed, plus details
6. Optionally set:
   - **Labels** (`bug`, `enhancement`, `docs`, `priority`, etc.)
   - **Assignees** (who should work on it)
   - **Projects** / **Milestone** (if your repo uses them)
7. Click **Submit new issue**.

## Write a Good Issue

Use a clear, action-oriented title (example: **Fix crash when saving profile**).

In the issue body, include where relevant:

- Context/goal (what you were trying to do)
- Steps to reproduce (for bugs)
- Expected vs. actual behavior
- Environment (OS, version, browser, etc.)
- Proposed solution or hints, if you have ideas

## Create an Issue from Code, Comments, or Discussions

### From an Existing Comment or Review

1. Click the `...` menu next to the comment.
2. Choose **Reference in new issue**.
3. Select the target repository if prompted.
4. Edit the title and description.
5. Click **Create issue** → **Submit new issue**.

### From Code in a Pull Request or File View

1. Select a code range.
2. Click the `...` menu next to the selection.
3. Choose **Reference in new issue**.
4. Fill in details and submit.

### From a Discussion

1. Open the **Discussions** tab, then a specific discussion.
2. In the right sidebar, click **Create issue from discussion**.
3. Adjust title/body and submit.
